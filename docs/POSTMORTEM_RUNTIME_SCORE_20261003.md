# CASMI26 v2：五小时耗时与成绩退化复盘

日期：2026-10-03。对象为已实际成功运行、提交并评分的冻结 v2（源 `a45c65e9`）。公榜为 **0.171**，旧化学先验 v1 为 **0.176**。本次只复核已有日志和源码，没有启动新的训练或提交。

## 1. 首要结论与执行责任

这次长时间等待的主要原因是发布流程设计不当：比赛 Notebook 调用了完整研究入口，把数据准备、双臂训练、三组研究验收以及最终测试推理放在一次执行中。提交后隐藏环境还要执行这套流程。研究计算有其用途，但它不应成为每次比赛推理必须支付的成本。

此前应先做小批量耗时测量、区分研究入口与发布入口，并在明确告知“GAN收益尚未证实”的前提下安排实验性提交。这些工程检查没有在正式执行前完成，导致用户付出了不必要的等待。既有研究验收并非全部没有价值，但整个流程的成本与结果不匹配。不能把问题归咎于用户选了较弱GPU。

## 3. 代码中已确认的工程问题

### 3.1 研究流程直接进入比赛发布

`kaggle_release_gan/build_notebook.py`调用 `adversarial_release.run`。这个入口无条件先 `prepare`、`train_pair`，再完成991题开发、994题未知和880题已知验收，最后才处理实际test。研究队列共2,865题，本次可见test400题，但这些队列难度与图编辑触发率不同，不能简单按题数推算加速倍数。

训练的 `seconds_per_arm=1800` 只限制训练循环；没有准备、验收或整次运行预算。即使训练3分钟结束，这个限制也不会阻止后续运行数小时。隐藏执行的逐阶段时间没有下载到，不能把可见时间当作隐藏实测时间，但重复研究入口可由源码直接确认。

### 3.2 对不使用新排序的题目仍做新排序

`Ranker.rank`先计算候选规范指纹、化学分数、analog分数和神经排序，之后才根据置信度门槛选择输出历史排名。研究验收需要各臂排名，因此这些计算有实验用途；正式推理只需要最终答案，应将保护分支提前。

**实际可见400题全部进入保护分支，GAN相对本轮历史分支改变答案0题、生成图0个。** 因而这400题的新神经排序没有进入最终答案，却仍支付了相关计算成本。这不意味着v2与旧v1的400题答案逐字相同，也不能外推隐藏题全部被保护。

### 3.3 CPU结构处理串行且存在重复计算

准备阶段遍历275,810个原始结构，先规范化后再选择最多60,000个训练身份；限制训练样本数并不限制规范化目录成本。日志中180,000→240,000结构用了2,190秒，即36分30秒，仅这一段就很慢。单个结构耗时未记录，尚不能确定具体异常结构或证明某个化学类别造成长尾。

规范结构、身份和神经指纹分别规范化；图编辑得到的规范身份还会再次计算。unknown、known和test建立多个Ranker，其指纹缓存分别重建。后两阶段的参考排除条件不同，必须保持隔离；可以共享纯结构特征，不能共享被某一验收条件过滤后的排序或参考集合。

图编辑每锚最多256次尝试、每题取最多32个合格新图。它要检查合法性、连通性、质量、分子式和规范身份，且循环串行。不能为加速只取前32次原始编辑，否则会改变候选协议。

### 3.4 模型重载回CPU，双GPU没有自动并行

训练器实际使用CUDA，但 `load_generator` 默认 `device="cpu"`，发布入口没有覆盖它。训练之后的指纹预测在CPU执行。T4 x2不会自动分摊RDKit、NumPy检索和逐题循环；四个PyTorch线程也不是四个RDKit工作进程。改用GPU推理可减少其中一部分耗时，但现有日志没有测量其单独占比，不能承诺换卡解决五小时等待。

## 4. 为什么更慢却更低分

公榜0.176→0.171，下降0.005，约为旧分数的2.84%。耗时增长来自额外研究和候选处理，不代表模型获得了更多有效信息。四个具体问题有实证支持：

1. **GAN没有稳定增益。** 相同数据、候选和路由下，unknown MRR仅增加0.000146，95%配对区间[-0.000657,0.001071]；known下降0.000611，区间[-0.001639,0.000442]。两者都跨零，不能作为稳健升级证据。
2. **新图投入没有补上真值。** unknown生成16,807个按题去重图、known生成3,872个，新增精确真值覆盖均为0。它们仍占用最终排名槽位，存在干扰风险；需要关图对照才能测量其净损害，不能仅凭零覆盖确定全部公榜下降由图编辑造成。
3. **路由可能压掉已经正确的预测。** 未知案例 `FQNCLVJEQCJWSU` 中，监督与GAN原始排序都把真值排第一，但置信度约0.917使流程保留错误旧排名，最终真值前25缺失。`CJGRGYBLAHPYOM` 中GAN原始第一、监督第二，固定保留旧首位及融合后，两者最终都未进入前25。
4. **候选缺真值是硬上限。** 未知验收仅106/994题在扩展质量候选池有真值，路由可用池101/994。神经指纹再准确也不能把不存在的结构排出来。仅五条化学规则，unknown实际命中18/994题，也无法约束绝大多数查询。

v1→v2还同时改变保护门槛0.5→0.75、神经融合权重、图候选和身份处理。没有同池纯监督版本的公榜对照，也没有隐藏真标签，**无法将公榜−0.005全部归因GAN或定位隐藏哪几题变差**。代理验收和比赛来源分布不同，小幅本地收益不保证公榜收益。

两臂在第6轮以后出现训练probe改善、dev BCE恶化，支持后期过拟合/目标错配迹象；但实际可见权重选第6轮。不能声称部署了最后一轮而因此退化，也不能把过拟合认定为唯一主因。GAN预测不同噪声平均仅改变约0.7/2048个阈值指纹位，潜变量利用弱；它生成的是指纹，未证明通用分子图生成或库外精确恢复。

## 5. 下一步的顺序与止损标准

先做工程拆分，再做科学改动，两者分别验收：

1. 保存研究产物和版本哈希，发布入口只加载固定权重、预处理、结构特征和索引，针对实际挂载test计算答案。移除比赛入口中的训练和2,865题研究验收。不得用可见CSV或ID查表代替隐藏预测。
2. 在同一checkpoint下验证原Ranker与新入口逐题候选身份、顺序、Top25一致；受保护题走提前返回路径。历史analog指纹与规范神经指纹保留各自定义。
3. 用小批量测量准备、参考加载、索引、指纹、规则、图编辑、排序、统计和输出，记录CPU/GPU及峰值内存，先确认主要瓶颈再优化。记录长尾结构，保持规范化语义，不因耗时随意跳过化合物。
4. 按下一轮PRD冻结新验收及路由/规则/关图对照，GAN先作为研究臂。只有预声明标准通过才作为推荐升级；没有稳定收益就保留最好方案。
5. PRD的可见400题推理目标为20分钟、45分钟判定工程验收不合格。这是拟定验收线，尚未实现或证明能达到。不能承诺未来每次必定十分钟，也不再把没有总预算的完整研究流程直接发布。
