## 1. 问题与产品目标

当前GAN v2真实公榜0.171，低于旧最佳0.176。完整实验耗时5小时37分钟，但GPU训练仅约180秒；比赛提交还重新执行研究验收。未知参考任务中，真结构多数不在质量候选池，错误保护又会挡住已经排第1的真值。新增图精确覆盖为0，GAN同条件收益区间跨零。

下一轮需要一个能快速执行、可追踪失败环节、能公平比较改进的比赛发布流程。核心用户是运行实验和验收结果的项目成员；用户应能看到版本、阶段进度、实际耗时、失败原因、对照结果和真正Kaggle分数。

### 1.1 本轮必须交付

1. 可恢复的研究训练/验收入口，以及单独的离线比赛推理入口。
2. 同权重推理一致性证明、缓存版本机制与完整身份/候选审计。
3. 新留出协议下的路由改进实验；化学规则扩展作为预先声明的独立比较。
4. 冻结模型、规则、数据和代码的发布清单；合法动态CSV及Kaggle提交状态证据。
5. 一份真实结果报告，包含通过、未通过和回退理由，允许如实结论为“没有提升”。

### 1.2 不作为本次必须范围

不训练大规模通用分子图解码器，不下载整个PubChem，不按公榜反馈逐次搜门槛，不将旧可见CSV复制为隐藏预测。结构解码器作为后续独立研发任务，先验收精确重建。多GPU并行仅在测量证明GPU瓶颈后实施。

## 3. 用户流程与运行状态

研究：读取数据与manifest → 拆分并锁定验收 → 准备缓存 → 训练对照 → 开发选择 → 冻结协议/权重 → 一次验收 → 产出通过/拒绝决定。

发布：读取已审核发布包 → 自检 → 读取实际test → 检索/推理/化学重排 → CSV验证 → 保存正式Notebook版本 → 提交 → 等待隐藏重跑 → 保存Succeeded或失败证据。

状态必须区分 `prepared`、`training`、`development_selection`、`frozen`、`acceptance_complete`、`release_verified`、`notebook_running`、`submitted_hidden_running`、`scored`、`failed`。提交按钮点击成功不等于比赛出分；Notebook版本号不等于比赛submissionId。

每阶段记录已完成题数、总题数、墙钟时间、峰值内存、缓存命中率和错误数量。长阶段至少每60秒或每固定查询批次写一次持久进度；展示估计剩余时间时同时标注估计依据和波动，不静默数小时。

## 4. 数据与防泄漏要求

### FR-01：重新划分下一轮的训练/开发/验收

本轮994题、880题以及报告精选案例已经用于诊断，不再称为下一轮未触碰的独立验收。它们可继续用于工程回归和机制复现。

下一轮使用官方规范身份定义的确定性新拆分，并从头训练需要比较的监督模型/GAN。新验收身份必须从下一轮两臂拟合及开发选择中排除；不能用旧权重在其已经训练过的新留出身份上证明神经外推。

建议预设上限：训练60K身份，开发2K身份，新验收2K身份，每身份最多2张谱。验收不足2K时报告实际规模；开发选择后不以结果差调整样本上限。固定身份哈希盐 `casmi26-next-20261003-v1`、训练seed列表 `[20261003, 20261004, 20261005]`，拆分比例80/10/10；上限裁剪按另一固定哈希顺序。配置与实际身份清单均保存。

建立 `observed_cohorts.json`，列出本轮dev/acceptance、历史可恢复的诊断/开发集合和NP例子，新的验收选择排除这些已观察队列。历史队列无法全部还原时明确列出缺口；不能声称已与所有历史实验完全独立。新的拟合隔离保证针对本次重新训练，不倒推旧模型未见过这些身份。

known与unknown使用相同查询：unknown参考集排除该查询官方身份及别名；known仅保留可用的真实同身份参考，剔除查询本身及分箱谱向量副本。不得人工补入真值候选。两个场景分别记录真实样本数。

新骨架分层只作为诊断。若要声明严格骨架外推，另建骨架完全隔离的实验与模型，不能由现有分层替代。来源、仪器、模式、加合物、谱图数及质量区间必须分层报告，单一总体MRR不能掩盖目标域退化。

### FR-02：完整身份与输入审计

保存拟合身份清单、开发/验收清单、来源、排除原因、规范化版本、原始别名映射和预处理拟合清单。输入文件、目录、规则、索引、预处理、权重均记录SHA256。

检查训练/开发/验收身份交集为零、预处理仅拟合训练；query-copy删除计数可复核。验收真值只能进入评价器，不能被ranker、候选生成器或路由调用。

## 5. 候选和排名要求

### FR-03：每题诊断漏斗

每题保存以下字段：源目录是否含真值、质量与加合物资格、完整候选身份池、初始/扩展/生成候选来源、原始排名、化学后排名、路由后排名、首次正确排名和淘汰阶段。完整逐题记录被Git忽略，聚合与精选案例可发布。

主报告分解为：缺库、在库但质量不合格、在池但排序差、规则无资格、融合退化、错误保护、身份重复。分别报告candidate recall、Top1/5/25、总体MRR和已覆盖子集MRR。

### FR-04：路由纠错

实现三个可比较策略：当前固定旧首位策略、允许融合修改首位策略、经过开发校准的条件保护策略。禁止继续把余弦相似度直接称为正确概率。

开发校准可使用Top1相似度、Top1/Top2差距、质量误差、多谱一致性、模式/加合物和候选证据冲突等无真值推理特征。运行时不能查询“真值是否在池”或known/unknown评价标签作为路由输入。

校准与开发选择使用身份级交叉验证，保存折分、模型及阈值。预设开发候选最多6种组合，配置列表先提交再执行，不能不断增加组合直到开发变好。已知任务保护与未知任务纠错共同作为开发选择约束。

候选池相同的对照中，只改变路由；保护不得悄悄换成旧候选池。需要保持原V2保护行为的臂应明确标记“旧池回退”，与仅固定首位的差别分开记录。

### FR-05：化学先验及规则适用范围

V2已对所有查询抽取证据，下一轮复用此能力，并允许证据参与保护决策。新增规则必须记录质量、离子/中性丢失类型、模式、加合物、电荷资格、SMARTS、出处、适用限制、权重与规则版本。

先审核己糖类规则的Na/NH4适用范围，并扩展有来源的常见碎裂先验。无可靠依据的条目留在候选词典，不进入生产规则。MS-FINDER或其他词典须先核验许可与质量，不默认全表可分发或所有条目都适用。

规则审计至少区分：质量命中、模式/加合物有资格、真值结构支持、错误结构支持、实际排序改变。抽样保留错配及无效条目。重复谱与重复峰不能无限累加证据；缺失峰不直接删除结构。

初始质量匹配容差沿用V2实现定义。任何容差、强度门槛或规则权重变化都属于科学实验，不能作为缓存优化混入。化学约束是否使用硬过滤，须有单独的可靠性证据；本轮默认软加分。

### FR-06：结构生成与GAN消融

图编辑保留相同锚点、seed、尝试数、质量/分子式/电荷检查和去重。纯图消融必须在相同排序器与路由下比较有图/无图；不能比较同时改变神经分支的expanded_chemistry来声称图贡献。

GAN与监督臂共享训练身份、预处理、G初始化、数据顺序及候选池，记录真实G/D更新数和选入权重。噪声指纹差异、位频率、有效多样性是诊断，不代替结构命中指标。

三seed按同一拆分训练；主要验收预先选择一个开发最优配置，以三个seed的指纹概率等权平均形成固定预测。不能看验收后选seed。单seed结果作为敏感性分析，不把同一批分子的三次预测当作三倍独立样本。

## 7. 指标、统计与发布判定

主指标为unknown MRR@25；known为保护约束。按官方规范身份配对bootstrap，建议10,000次，随机种子固定20261003。known/unknown因查询重叠分别报告，不当独立样本合并。

确认性主比较仅一个：开发选定候选−A1。按第2节门槛判定。其余比较明确标为探索性；如要对多个次要比较宣称显著，需在协议中加入多重比较控制，不依据多个95%区间择优宣称成功。

输出还需包含：来源/仪器/模式分层、规则触发/误匹配、错误保护率、protected回退丢失覆盖、覆盖内MRR、生成精确新覆盖、重复槽位、峰值内存与总耗时。

| 实际结论 | 发布动作 |
|---|---|
| 格式、身份隔离或工程等价不通过 | 禁止提交新版，修复工程并保留失败记录 |
| unknown主门槛通过且known保护通过 | 发布冻结的唯一候选，最多一次预设科学提交 |
| unknown未通过或known明显退化 | 记录未通过；保留旧最佳，不临时调参再用同一验收验证 |
| GPU训练成功但排序未提升 | 作为真实负结果，不用loss或训练时长替代MRR |
| 公榜降低 | 保存真实分数；不把它再反向用于本轮验收调整 |
| 隐藏执行工程失败 | 仅修必要工程问题；冻结新版本、保留原失败与修复差异 |

## 8. 推理工程与资源预算

### FR-07：拆分研究和正式推理

研究入口执行准备、训练、开发和验收，产出审核发布包。比赛Notebook只加载权重、训练拟合预处理和必要索引，对实际test执行推理，不训练、不运行dev/unknown/known研究队列。

正式入口必须处理变化的test ID、题数、模式、质量、谱图数及元数据未知类别。元数据缺失使用训练固定的unknown映射，不在test重新拟合。不能按可见molecule_id查表或将可见CSV直接返回。

训练包记录训练身份排除清单。固定权重推理不声称与隐藏test变化后重新训练的V2全过程等价。正式发布前核实当前比赛对外部数据、预训练权重、离线依赖和执行时限的规则；在PRD阶段未核实的限制不编造具体值。

### FR-08：缓存、并行和恢复

纯结构缓存键包含输入SHA、RDKit版本、规范化设置、指纹配置、规则SHA及原始结构。神经规范指纹与历史analog指纹使用不同命名空间。阶段可共享纯结构特征，不能共享含known/unknown不同排除条件的最终候选或排名。

生成图可复用已验证身份，不重复规范化；保留原随机尝试序列和稳定tie-breaking。先测纯结构预计算并行，再测逐查询并行；进程数候选1/2/4，按实际内存及吞吐决定，不能假设线性加速或每进程复制全部谱库。

缓存、阶段产物和checkpoint采用原子写入，恢复时逐项核对哈希，旧规则/旧预处理缓存不得误复用。OOM或损坏缓存应有明确失败记录或确定性的等价回退；回退不能静默改变排序。

| 阶段 | 初始预算/目标 | 超预算处置 |
|---|---|---|
| 小规模工程一致性 | 100题，目标≤15分钟 | 定位缓存/索引/并行问题，不扩到全量 |
| 完整旧队列回归 | 用现有994/880病例仅作工程回归 | 复用池与特征；报告实际耗时 |
| 新研究全流程 | 总墙钟目标≤2小时；训练最多30分钟 | 未执行验收前调整工程预算并重冻结；解封后不得临时缩短选择训练臂 |
| 正式可见400题推理 | 目标≤20分钟，45分钟未达标 | 不把性能未达标叫运行完成；分析阶段耗时 |
| GPU | 首轮仍使用可用T4配置 | 先实测GPU/CPU瓶颈；不依赖双卡自动并行 |

规模与挂载环境变化可能影响预算。超时不能静默输出截断候选、减图或较差模型；若需要降级发布，应作为新的预先冻结方案独立验收。已冻结研究阶段应按确定的相同预算完成两神经臂。

公开GitHub只提交源码、协议、聚合指标、精选案例及截图。完整训练清单/病例是否可公开按数据许可检查；原始谱、完整排名、模型和大缓存默认继续被Git忽略，模型作为Kaggle许可范围内的离线输入管理。

## 11. 必测场景

| 场景 | 预期结果 |
|---|---|
| 候选真值存在、神经首位正确、历史置信度高 | 新路由能按预设规则纠错；不直接用真值决定 |
| 真实同身份参考可用 | 保持known保护，剔除query副本 |
| 诊断质量匹配但加合物无资格 | 留痕，不误计为已支持化学证据 |
| 多张重复谱及重复峰 | 证据强度不随复制无限增加 |
| 原始键不同但官方身份相同 | 去重、训练排除和评分一致 |
| 扩库新增很多竞争结构 | 原覆盖损失单独呈现，不能只报新增命中 |
| 图合法但不是真值 | 生成计数增加，精确新覆盖仍如实为0 |
| test为37/400/800题，ID与顺序变化 | 动态输出完整ID，不查表固定400题 |
| 空谱、缺失元数据、罕见加合物 | 预设确定性处理；错误/回退计数可审计 |
| 权重或规则SHA不一致、缓存损坏 | 明确拒绝或等价重建，不静默使用旧资产 |
| CPU/GPU推理微小数值差 | 报告容差；最终Top25顺序不能未经解释变化 |
