## 0. 最重要的结论（先读这里）

1. **GitHub 仓库不是当前方案。** `main` 只有 1 个提交，是 2026-09-29 的快照，最佳公开分 0.176。Kaggle 账户实际有 47 次提交，当前最佳是 **0.495**（2026-11-19，Notebook `xiaoyuzhoux120/casmi26-nightly-frp5-20261119`），排行榜第一是 **0.554**（2026-11-24 查询）。10 月以后的全部工作（nightly 构建脚本 `scripts/build_*.py`、H-A-xxx 假设编号、验证数据包）都不在仓库里。
2. **当前 0.495 方案是公开 Notebook 谱系的复现加微调**，不是自研主干。该谱系（Gluzdov 0.465 冻结管线 → 0.466 神经打分 → 0.468/0.472 leader-safe RRF → … → 0.487/0.495）在公开区已高度同质化：2026-10-28 时 112 个 ≥0.460 的公开 Notebook 中 103 个挂载同一份 v4g 资产。该 Notebook 自己记录："前十名队伍没有一位是这 974 个公开 Notebook 的作者"。从 0.495 到 0.554 的差距（约 +0.06，公开榜约 15 个分子）不太可能靠继续调这一谱系的常数获得。
3. **验证体系是最大的方法学瓶颈。** 过去三个月里，本地/离线指标多次与公开榜方向相反（仓库自研：本地提升 → 公开 0.162/0.169/0.173 均低于 0.176；Kaggle 谱系：自训 FPNet 离线 Tanimoto +26.5%，7 次替换全部掉分 0.418–0.443；邻居网络离线 −0.0033，榜上 +0.001）。原因可以定位，见第 3 节。
4. **今天的 nightly `casmi26-nightly-pablo506-20261124` 状态为 ERROR。** 云端无法下载其日志：`www.kaggleusercontent.com` 不在网络白名单内（实测 403）。

## 3. 验证与泄漏审查

**做得好的地方（仓库）：** 按 InChIKey14 哈希做分子级切分；预处理只在训练集拟合；每轮使用新的独立留出集并冻结选择；known 场景去掉查询谱及其完全副本；记录 bootstrap 置信区间。没有发现训练/验证标签直接泄漏。

**问题（按影响排序）：**

1. **验证分布错配（最严重）。** 隐藏集是 timsTOF NP，仓库验证集约 2/3 是 enveda-180 合成分子，且"未知"场景的候选池不保证含答案（召回 8–12%）。而第 2 类按定义一定在 PubChem/COCONUT 中，正确的代理应是"答案在候选库中、但无参考谱"的 NP 分子。
2. **Kaggle 谱系的离线面板饱和且被反复查看。** 验证 Notebook 使用"truth-injected 160 pools"（把正确答案注入候选池，160 个身份，且标注为 prior-inspected）和 NP panel（MRR ≈0.97）。注入真值跳过了候选生成这一关键环节；反复在同一面板选参数会过拟合。
3. **按公开榜选参数。** 公开榜约 125 分子，±0.002 的运行间抖动（时间守卫跳过可选阶段）与 1 个分子的变化同量级。许多决策基于 0.001–0.004 的榜差，私有榜（约 70%）上存在回退风险。
4. **指标 key 不一致**（见第 2 节，约 4%）。
5. **相似结构未分组。** 切分只按 InChIKey14，近似类似物（同骨架）可跨 train/dev，对神经指纹模型的估计偏乐观（推断，未量化）。
6. **非确定性。** 仓库 NEXT_STEPS 已记录：平台与本地完整排序仅 263/400 相同，同分未稳定排序；Kaggle 谱系同代码重跑 ±0.002。

## 4. 现有方案架构（0.495）

运行顺序（Kaggle 谱系，T4 GPU，禁网，约数小时）：

1. 冻结 0.465 管线：训练集 2.54M 谱 entropy 搜索 + 质量平移类似物传播 + COCONUT/PubChem/ChEBI/LIPID MAPS/LOTUS 候选池（约 71 万结构）+ GLACIER/ICEBERG 正向谱预测融合。
2. 神经谱–结构打分器（公开 v1 + v80 z-score 集成）与检索做 RRF，rank 1 权重 0.25、rank 2–25 权重 0.75（leader-safe）。
3. MetFrag-lite ≤2 键断裂碎片解释打分（只取它对 rank 1 的移动）。
4. DocPrior（PubChem 文献数/专利数、NP 数据库成员资格）+ timsTOF 质量误差先验 + InChIKey14 去重补位。
5. 邻居网络 N-1c（测试分子间 modified cosine ≥0.6 共享候选证据，λ=0.35，D-L1 变体）。
6. 外部谱库 rank-1 覆盖（GNPS-full 重建库，cos ≥0.80、≥4 峰、10 ppm）。
7. FR 3-25 学习型碎片重排、P5 tail 新候选插入 3–25 位。

各层公开榜增益：0.465 → 0.472（RRF 权重）→ 0.477（碎片校核）→ 0.480–0.487（先验/外部库）→ 0.488（FR）→ 0.490（P5）→ 0.494–0.495（邻居网络）。**后段每层只有 +0.001–0.004，即 0–1 个公开榜分子，统计上无法和噪声区分。**

## 5. 主要瓶颈（按优先级）

| # | 瓶颈 | 证据 | 影响估计 |
|---|---|---|---|
| B1 | **没有能预测私有榜的本地验证** | 第 3 节；离线与榜反向的多次记录 | 无法安全地做任何非微调改进 |
| B2 | **代码与实验资产不在版本库** | 仓库停在 9/29；nightly 构建脚本、验证数据包缺失 | 难复现、难协作、各研究线程无法在真实基线上工作 |
| B3 | **第 2 类的候选生成与排序**（推断为主要失分区） | 只用库检索 0.140，加 COCONUT 0.176；谱系主体收益来自 PubChem 通道、正向模型和神经打分。若第 1 类 MRR≈0.9，则第 1 类约占 15–20%，其余大部分分数在第 2/3 类 | 最大的上升空间；需要 PubChem 级候选 + 更好的谱–结构打分 |
| B4 | **rank-1 决策脆弱** | 谱系记录：让神经模型更自由地改 rank 1 时 0.472 → 0.448/0.359；自训模型替换全部掉分 | 打分器的校准（何时信任）比打分器本身更关键 |
| B5 | **领域偏移** | 训练谱 45% 为 enveda-180 合成分子（同仪器、不同化学空间）；NP 谱来自其他仪器 | 神经模型在 NP 上泛化有限 |
| B6 | **标签噪声与指标 key 不一致** | 5–10% 高 ppm 误差；3.9% key 不一致 | 小但确定的损失，修复成本低 |
| B7 | **运行时间与非确定性** | 时间守卫导致 ±0.002；9 h 上限；今天 nightly ERROR | 影响最终提交的可靠性 |

第 3 类（不在 PubChem）目前没有任何组件真正处理（P5 tail 的类似物变换生成最接近）。比例未知，但在 de novo 很难的现状下，投入产出比低于 B3/B4。

## 6. 给后续阶段的建议（不改模型，只定方向）

1. **先把 0.495 管线的完整源码与构建脚本放进独立 Git 分支**，并固定所有输入数据集版本的 SHA-256。
2. **建立"类别感知"的本地验证集**：
   - 第 1 类代理：`enveda-np-examples` 作查询，参考库排除查询来源。
   - 第 2 类代理：NP 来源分子（非 enveda-180），删除其全部参考谱；候选来自 PubChem/COCONUT 质量窗口，**不注入真值**，并报告召回。
   - 用官方 tautomer InChIKey14 计分；按骨架分组切分；固定一次性终验集。
   - 用已有的 47 次公开榜成绩做校准：只有当本地指标能对这些已知提交排对顺序时，才信任它。
3. **两个确定性低成本修复**：训练数据按 `precursor_error_ppm` 过滤；全部去重和评估改用指标同款 key。
4. 研究线程优先级：B3（PubChem 候选 + 谱–结构打分/重排）> B4（rank-1 置信度校准）> B5（timsTOF 领域适配）> 第 3 类生成。
